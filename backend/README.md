# Solutions Media backend

Cloudflare Worker providing authenticated administration, D1 content/settings, and R2 media. Resources and local state are separate from Lida.

## Local setup

From `backend`:

```powershell
npm install
npm run setup:local
npm run db:migrate
npm run dev
```

`setup:local` generates a random local password and signing secret in the ignored `.dev.vars.dev`. It preserves existing credentials on later runs. Sign in as `admin`; find the password in that file's comment. Do not reuse local credentials for production.

Migrations seed 22 records from the Solutions Media website. Local state is stored under `.wrangler/solutions-media`, separately from any earlier Lida state. The seed migration uses INSERT OR IGNORE and does not overwrite edited records. `scripts/seed-content.mjs` prepares the initial seed from the website store; do not regenerate an already-applied migration to update live data; use the admin instead.

Run the admin and client dev servers as described in [admin setup](../admin/README.md).

## Deployment configuration

Production is deployed with dedicated Solutions Media resources:

- Worker: `solutions-media-backend` at https://solutions-media-backend.onochieazukaeme.workers.dev
- D1: `solutions-media-content` (`bb8a759c-e9e8-4a7c-835f-b353d3e51c5c`)
- R2: `solutions-media-media`
- Admin Pages: `solutionsmedia-admin`
- Website Pages: `solutionsmedia-app`, production branch `solutions-media`

The three database migrations are applied. `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, and `JWT_SECRET` are installed as Worker secrets. Production login details are stored in the ignored `.wrangler/solutions-media-production/admin-credentials.json`. `scripts/setup-production-secrets.mjs` prepares these files idempotently; it does not rotate existing credentials.

For a fresh environment:

1. Create a D1 database named `solutions-media-content` and R2 bucket named `solutions-media-media` in the intended Cloudflare account.
2. Replace the placeholder `database_id` in `wrangler.toml` with the new Solutions Media database ID. Confirm `ALLOWED_ORIGINS` contains the actual website and admin origins.
3. Set `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH`, and `JWT_SECRET` using `wrangler secret put`. The password hash format is `pbkdf2-sha256$100000$salt$digest`, generated by `hashPassword` in `src/auth.js`. There is no default production password.
4. Apply the migrations to the new database with `npx wrangler d1 migrations apply CONTENT_DB --remote`, then deploy the Worker.
5. Set `VITE_API_BASE_URL` to that Worker's URL in both frontend builds. Set `VITE_SITE_URL` in admin to the website URL and `VITE_CONTENT_SOURCE=admin` in the public website build.
6. Build and deploy the admin and public website.

The website's Cloudflare production build settings and local `.env.production.local` select `VITE_CONTENT_SOURCE=admin` and the Solutions Media Worker URL. `static` mode remains available for an intentional standalone build. Do not point either app at Lida's Worker.

To redeploy the website, build `client`, run `node scripts/prepare-site-upload.mjs` from `backend`, and deploy the printed staging directory using `wrangler pages deploy <directory> --project-name solutionsmedia-app --branch solutions-media --commit-dirty=true`. Staging excludes unused purchased-template source/archive files and unrelated Lida documents.

The contact-email endpoint additionally requires a verified sender and `RESEND_API_KEY`. Mail delivery is not enabled by the local setup. Website contact-form redesign is outside this admin restoration.

## Validation

`npm test` checks password hashing and token verification. `npm run types` regenerates Worker bindings. From `admin`, `npm run test:content` runs real local backend/browser integration tests using isolated `.wrangler/solutions-media-content-tests` data and R2 storage.

Cloudflare references: [local secrets](https://developers.cloudflare.com/workers/local-development/environment-variables/), [D1 migrations](https://developers.cloudflare.com/d1/reference/migrations/).
